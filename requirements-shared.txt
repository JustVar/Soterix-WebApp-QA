# The shared QA pipeline, pinned to a tag.
#
# Kept OUT of requirements.txt on purpose. This repo is private and so is
# the package, so installing it needs a credential - and measured on a real
# developer machine, `git@github.com` is refused: this team's git runs over
# HTTPS with no SSH key configured. A git+ssh line in requirements.txt would
# therefore break `pip install -r requirements.txt` for everyone locally
# while working perfectly in CI, which is the worst way round.
#
# CI installs this file after loading the read-only deploy key.
# See .github/workflows/collect-gate.yml.
#
# LOCALLY, do not use this file. Install the sibling checkout instead, which
# needs no credential and lets you test a package change before tagging it:
#
#     pip install -e ../soterix-qa-shared
#
# Pinned to a TAG, not a branch. The package's CI refuses a tag whose
# [project] version does not match it, because installing an unchanged
# version against a new pin is a silent exit-0 no-op that leaves the old
# code in place.
soterix-qa-shared @ git+ssh://git@github.com/Soterix-Systems/SOTERIX-QA-SHARED.git@v0.16.0
