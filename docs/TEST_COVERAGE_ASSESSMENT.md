# Test coverage assessment, 09/08/2026

What each product test proves when it passes, and how strong its oracle is.
Fourteen readers each took one module group and read every test function,
its docstring and the page-object or client methods it calls (508 tests:
437 in this repo, 71 in Soterix-API-QA). A second, skeptical reader then
re-checked every "none" verdict and every dubious claim against the code;
where the two disagree the note says so. This is a reading of the code on
one day, not a run: use it to pick what to strengthen, and re-read a test
before acting on its line. The living list of tests is
`docs/TEST_INVENTORY.md` (generated); this page is the judgement.

**Oracle scale.** strong: asserts an observable product outcome against an
expected value or state change. weak: asserts only presence or visibility,
or restates its own setup. none: no assertion about the product, or a test
that cannot fail or always skips.

## admin-core (51 tests: 17 strong, 33 weak, 1 none)

Product: NexaiQ-Core (web app). Files: test_admin_audit_trail.py, test_admin_general.py, test_admin_rules.py, test_admin_sites.py, test_admin_users.py.

**What these tests genuinely verify**

- Audit Trail opens from the General card's View button and shows the 'General > Audit Trail' breadcrumb, a table with the columns Username / Role Type / Date & Time / IP / Action, and records with a dd-mm-yyyy date and hh:mm time
- The audit breadcrumb returns to the General cards page
- Admin sidebar tabs (Users, Sites, General, Rules) render and can be switched between; Admin survives a browser refresh
- The rule picker offers Entry-Exit; the full wizard creates a rule of each of the six types on the configured camera and the rule lists exactly once by name
- A rule can be deleted by name and no longer lists; the Mute Notification icon flips when clicked; the Edit icon opens the details drawer (exercised as a precondition)
- Sites grid/list view toggles both ways; site cards carry Online/Offline markers and Version lines
- Opening a site card shows the detail (Groups) and unmounts the list; the camera sort toggle changes the camera order
- Camera group create and rename forms are accepted; a group deleted through the Groups dropdown leaves the list
- In-site camera search filters to exactly the configured camera and clearing restores the list
- Add User form accepts input and closes; role filter offers Admin/Operator/Supervisor and shows the chosen role
- A user's status switch flips and flips back; deleting a user removes a row and the server accepts the request

**Gaps: product behaviour in this area with no test**

- Audit Trail 'Today' range filter (named in the module docstring) has no test; no test changes the range or checks the record set changes
- No test correlates an action with an audit record (e.g., the test's own login producing a 'User X logged in.' row, or a rule/user change appearing in the trail)
- Audit Role Type and IP cell contents are never checked; only Username and Action non-emptiness
- Rule search, site search and user search are only checked for input echo; no test proves the list actually filters or that a no-match search shows an empty state
- Rule wizard step validation is untested: Next disabled without a device or region, Exit from the wizard, and the created rule's type/site/camera shown in the list or details drawer
- Rule details drawer content (devices, schedules, created/modified audit) and Unmute are never asserted; the notification popup/push toggles in the page object have no live test since the form disappeared
- A created camera group is never looked up in the Groups list, and a renamed group is never found under its new name; group camera membership is not checked in the UI
- Sites list view content (rows after the toggle), the site card Options menu (img[alt='Options']) actions, offline site behaviour and the sort's actual alphabetical order are untested
- A newly added user never appears in the list (name/email/role checked), no user edit test, no form validation (duplicate or invalid email, required fields), no check that the role filter changes the rows, no check that suspension persists after reload
- Event Wall from Admin > General is only touched by a no-op title click here; the real config coverage is in tests/ui/event_wall/ (out of this group)
- Admin sub-sections named in the page object's nav skip list (Licenses, Integrations, Dashboard) have no tests in these files; I am not confident which of these are Admin tabs versus top-level nav

## admin-lpr (57 tests: 23 strong, 32 weak, 2 none)

Product: NexaiQ-Core (web app), LPR module. Files: test_lpr_camera_selection.py, test_lpr_events.py, test_lpr_navigation.py, test_lpr_grid_and_timer.py, test_lpr_widgets.py, test_lpr_playback.py, test_lpr_views.py, test_lpr_operations.py.

**What these tests genuinely verify**

- Creating an LPR list of type White List through the Create List dialog adds a row with that name (and every list-owning test's teardown deletes its list through the row's delete icon and confirms the row is gone).
- On a list's Plate page the filter panel opens and closes from the Filter icon; Apply switches to the Search Results view; Reset returns to the Plate page.
- Navigation markers: Admin > LPR shows the Lists page; Categories tab shows Add Category; List tab returns to Lists; View icon opens a Plate page; sidebar LPR opens the camera page at /lpr.
- Layout picker on the LPR camera page: 1x1/2x2/3x3 give exactly 1/4/9 empty tiles and the clicked button becomes active.
- Starting streams from the Locations & Cameras panel: single camera via hover checkbox or drag, whole All Cameras group via hover checkbox or drag; Reset View clears all streams.
- Clicking a streaming tile activates it (live icon appears).
- Playback timeout popup (Set Timeout Duration) opens over a playing stream, shows Save/Cancel, its duration dropdown lists 30 and 45 Minutes, and Cancel closes it.
- Event feed: cards carry a full time-and-date stamp; clicking a card opens a clip player with a video and position/duration readout; the close icon removes the video; the full screen icon engages browser fullscreen; Share/Export/Create Link and Backward/Forward icons are present; the feed filter panel opens with Cameras/Duration/Apply.
- An Insights widget created with the License Plate Recognition description appears as exactly one card when searched in the LPR camera page's Widgets panel and can be dragged onto a tile (one empty tile consumed, widget rendered by name).
- Views page: the plus tab adds one view, each close icon removes one, and closing the last view is refused with an alert (not LPR-specific but housed here).

**Gaps: product behaviour in this area with no test**

- Plate management: Add Plate is only checked for presence; no plate is ever added, edited, deleted or searched, and the plate table contents are never verified.
- List editing: the Edit icon is never clicked; no rename, no type change; only White List is created although Black List exists (page-object comments); no duplicate-name or empty-name validation.
- List status toggle is never toggled and its on/off state is never read.
- Lists-page Search is never shown to filter out non-matching rows (test_search_lpr_list_by_name passes with a no-op search).
- Categories: Add Category is never clicked; no category create/edit/delete or assignment to a list.
- Filter panel: no criteria are ever entered; Search Results rows/table are never checked (LprPage.apply_filter_and_wait_results with its results_table wait is unused); the breadcrumb from Search Results back to Lists (lpr_breadcrumb, ensure_lpr_lists_page CASE 0) is never exercised despite a test named for it.
- Timeout popup: Save is never clicked; no duration is chosen, persisted or read back; the auto-timeout itself (stream stopping after the duration) is untested.
- Streams: only 'a video element attached' is checked; nothing verifies frames advance (Views has assert_tile_streaming, LPR does not), that the stream belongs to the chosen camera, or the Clear All control (clear_all_tiles falls through to Reset View).
- Event feed: the feed filter is opened but never applied; play/pause never pressed; seek never shown to move the position; Share/Export/Create Link never clicked; plate text, confidence, vehicle class and camera on a card are never checked; no card-to-clip identity check.
- Widgets: removing a widget from a tile, widget content, and any graph/category other than Line/Event are untested.
- Layout persistence across sessions is asserted in comments only; the flow that navigates from the camera page back to Admin > LPR Lists is untested; unused page-object methods click_view_icon_on_list, reset_filter_and_return_to_plate, lpr_breadcrumb, results_table indicate flows once planned and dropped.
