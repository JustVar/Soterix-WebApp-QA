# Adversarial Audit Findings (2026-09-01)

A 7-dimension adversarial audit (concurrency, multi-env, network, partial-outage, data-integrity, security, performance) of the shared QA pipeline and the spartan1 hosting. 32 raw findings, 30 confirmed after adversarial verification, 2 refuted. Each is listed with its disposition. Concrete scenarios were executed against real infrastructure, not reasoned about.

Two refuted (already safe by design): a mid-run WireGuard drop does NOT upload false FAILED verdicts, and an app outage during an armed run does NOT write FAILED to every case.

| # | Sev | Dimension | Finding | Disposition |
|---|---|---|---|---|
| 1 | high | security | Playwright failure-trace zips leak live QA session cookies and login credentials to the unauthenticated spartan1 archive | FIXED - basic auth on /qa-runs (spartan1), and traces/videos excluded from publish_run.py and nightly.sh (staged/rsync). Proven end to end. |
| 2 | medium | concurrency | Concurrent uploads to the same QA Touch run key make verify misfire and can overwrite a real failure with a pass | DEFERRED - operator convention (dedicated run per purpose); nightly stays unarmed until a run-key strategy is set. No code fix without a QA Touch coordination token. |
| 3 | medium | shared-state | publish_run.py overwrites the shared host index.html/health.html with the publishing machine's partial local view | FIXED - publish_run.py no longer sends the local index/health; nginx autoindex lists runs. |
| 4 | medium | multi-env | Auth storage-state cache is not keyed by tenant, so switching BOX silently reuses the previous tenant's session | FIXED - cache filename now carries base_url AND box; get_active_box default reconciled to config. |
| 5 | medium | multi-env | No run record distinguishes which tenant a run executed against - every writer captures ENV only, never BOX | FIXED (v0.25.0) - RunContext carries BOX; the run record and ledger row say which tenant a run hit, written only when set. |
| 6 | medium | multi-env | Tenant-specific test data (site, camera, chat user) is scoped per-ENV, not per-BOX, so the US box runs against India's data names | DEFERRED - config design: move per-tenant site/camera names under box, not env. |
| 7 | medium | multi-env | QA Touch upload has no binding between the armed run key and the tenant, and the read-back verify cannot catch a wrong-tenant upload | DEFERRED - same class as the concurrent-run-key finding; run key is operator-supplied. |
| 8 | medium | multi-env | UI and API-seeding fixtures use two unreconciled credential systems, so a single BOX run can seed data on one tenant and view it on another | DEFERRED - cross-repo: reconcile UI and API seeding credentials. |
| 9 | medium | network | Read-back verification fails open on a connection error with zero retries, so a flaky-network read-back is booked as a verified success | FIXED - a read-back that cannot run is unverified and saved for retry, not booked as success. |
| 10 | medium | network | A transient network error while replaying uploads misclassifies recoverable entries as permanently unreplayable | FIXED - transient failures stay queued; only run-absent cases are parked. |
| 11 | medium | partial-outage | QA Touch read-back verification fails OPEN on any non-429 error, so a partial QA Touch outage between write and verify reports a discarded upload as success and never queues it for retry | FIXED - same fix as the read-back-fails-open finding. |
| 12 | medium | partial-outage | When the QA Touch API key is absent from the environment (e.g. mid-rotation), the upload sink drops the run's results without saving them to the failure log — unlike every other failure path in finish() | FIXED - client-init failure now saves the run for retry instead of dropping it. |
| 13 | medium | data-integrity | Publishing a local run overwrites the shared server index.html/health.html with the publisher's partial local view | FIXED - see the index/health finding above. |
| 14 | medium | data-integrity | validate_run reconciliation reports false FAIL for case keys shared by several node ids with mixed outcomes | FIXED - validate_run folds to the worst outcome per case before comparing, the way the upload does; a genuine drift is still caught. |
| 15 | medium | performance-load | Archive caps run COUNT (100), never bytes: retain-on-failure traces of livestream tests reach ~920MB each and per-target retention keeps up to 20 near-duplicates | FIXED (v0.25.0) - the archive has a byte ceiling (QA_ARCHIVE_MAX_GB, default 10); oldest go until under, never the newest. |
| 16 | medium | performance-load | publish_run scp -r ships the entire run folder (including ~1GB traces) to spartan1 with no size check, dedup, or warning | FIXED - traces/videos excluded; the ~1GB payload is gone from publish. |
| 17 | low | concurrency | single-run guard has a TOCTOU acquire race (non-atomic read-decide-write lock), so two runs launched together in one clone both proceed | DEFERRED (low) - local per-clone race; make the lock acquire atomic. |
| 18 | low | concurrency | upload_failures.json read-modify-write is unlocked; retry_uploads.py overlapping a session's _save_failed_results can silently drop a fresh failure | FIXED (v0.25.0) - the failure log uses a shared file lock; 40 concurrent appends keep all 40. |
| 19 | low | multi-env | .env.template default BOX=us contradicts the config default (india) and all shipped test data, and two code paths disagree on the unset-BOX default | FIXED - get_active_box reads config[default_box]. |
| 20 | low | network | publish_run.py uses a single non-atomic scp, so an interrupted transfer leaves partial run folders and a truncated shared index on spartan1 | FIXED - publish scps to a hidden .pub-tmp then mv-s into place; an interrupted transfer leaves no partial run. Proven end to end. |
| 21 | low | partial-outage | publish_run.py runs scp with no BatchMode or ConnectTimeout, so an unreachable-but-not-refusing spartan1 hangs the publish on TCP connect, and a revoked key falls back to an interactive password prompt | FIXED - scp now runs with BatchMode=yes and ConnectTimeout=10. |
| 22 | low | partial-outage | UNVERIFIED: the spartan1 nightly CI (nightly.sh) and its read-only deploy-key failure mode cannot be audited — the script is not in any of the three repos | FIXED - nightly.sh, the prune script and the nginx snippet are now version-controlled under deploy/spartan1/. |
| 23 | low | data-integrity | Teardown/finalizer errors read green in the archive index and health.html while the uploader files them as Failed | DEFERRED (low) - reconcile teardown-error rendering between the archive index and the uploader. |
| 24 | low | data-integrity | _verify_upload treats any read-back error as success and saves nothing for retry | FIXED - see the read-back-fails-open fix. |
| 25 | low | data-integrity | A half-written upload_failures.json silently discards previously-queued retry results | FIXED (v0.25.0) - the failure log is written atomically (temp + os.replace), so a half-write never reads as an empty queue. |
| 26 | low | security | API test clients and the HTTP login helper send credentials with TLS verification disabled by default in non-prod | ACCEPTED - intentional for the QA self-signed cert; documented, not a change. |
| 27 | low | performance-load | Root cause of giant evidence: tracing captures screenshots+snapshots for every test and video is recorded for all 1425 tests, kept only on failure | PARTIAL - the giant-evidence root cause; traces now stay local, so the shared-host blast radius is closed. |
| 28 | low | performance-load | Index rebuild (every run) and health both json.load every summary.json before any window is applied | DEFERRED (low, perf) - apply the window before loading in index/health rebuild. |
| 29 | low | performance-load | Armed QA Touch upload puts the entire result set in the URL query string; request size and read-back pagination grow with mapped-case count | DEFERRED (low, perf) - large mapped-case runs grow the request; move to a body payload if it bites. |
| 30 | low | performance-load | Reporter holds every failure's screenshot bytes in memory for the whole session, then base64-encodes them all into one multipart upload | DEFERRED - see finding. |
